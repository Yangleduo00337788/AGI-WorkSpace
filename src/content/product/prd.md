PM 维护。一页说清「做什么、按什么顺序、怎样算过」。原型和思维导图放 [原型与排期](/product/prototypes)。

## PRD 摘要

- **问题：** 项目上下文无法被团队和 Agent 稳定复用。
- **方案：** 用本工作空间模版，七个角色各有一组 Markdown，在预览里改、写回仓库。
- **非目标：** 不做在线多用户编辑、不做通用 CMS。

## 业务流程

1. POM 建仓、填 [项目角色](/project/roles) 对接人。
2. PM 填概述、目标、定义、场景、PRD。
3. UIUE 出体验原则与稿件，完成 [设计交付](/design/handoff)。
4. RD 写架构、领域、契约；FE 写前端结构。
5. QA 写计划、用例；执行证据记在 [执行证据](/quality/evidence)。
6. OP 填环境与发布；POM 更状态、记决策。
7. 发布当天：QA 门禁 → OP 发布 → 状态页打勾。

## 排期

| 阶段 | 日期 | 产出 | 负责 |
| --- | --- | --- | --- |
| 立项 |  | 概述、目标、角色表 | PM / POM |
| 设计 |  | 体验原则、视觉规范、交互稿 | UIUE / PM |
| 研发 |  | 架构、契约、前端结构 | RD / FE |
| 测试 |  | 计划、用例、证据 | QA |
| 上线 |  | 环境、发布、回滚 | OP / POM |

## 验收标准

- [ ] 七个角色在系统配置中可勾选，写权限与 [项目角色](/project/roles) 表一致
- [ ] 每条角色职责在对应 MD 中有独立章节或独立文档
- [ ] 保存走本地文件，刷新后内容还在
- [ ] 目录与文档在侧栏和目录页都能区分
- [ ] （当前项目补充）
