PM 维护。用一段话让新成员或 Agent 在 2 分钟内理解这个项目。

## 背景

- **为什么要做：** 项目知识散落在聊天和各工具里，换人或上 Agent 就要重新问一遍。
- **现在怎么做、痛点是什么：** 没有按角色切开的单一工作空间，文档要么不能本地写回，要么必须会 Markdown。
- **相关系统 / 依赖方：** Git 仓库、设计工具、（若有）后端服务与 CI。

## 范围

**做：**

- 七个角色的模板文档与可写范围
- 静态文档壳：导航、搜索、主题、中英
- 预览编辑并写回 `src/content/`

**不做（非目标）：**

- 账号体系与云端多人实时编辑
- 用 CMS 代替仓库里的 Markdown
- 为每篇文档新建 Vue 页面

## 核心价值

1. 角色和目录绑定，职责可执行
2. 上下文在仓库里，人和 Agent 读同一份
3. 不会 Markdown 也能改文档

## 约束

- 时间：
- 合规 / 安全：授权目录只存在本机浏览器
- 技术或组织限制：写回依赖 Chrome / Edge
