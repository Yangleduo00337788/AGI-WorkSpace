PM 维护。把占位换成**当前项目**。这篇只回答「这是一个怎么样的项目」，工作空间怎么用见 [WorkSpace 指南](/start/guide)，模版思路见 [AGI-WorkSpace 新范式](/start/paradigm)。

## 一句话

AGI-WorkSpace（换成当前项目名称）：按七个角色组织的项目知识工作空间。人、Agent、仓库读同一份 Markdown。

## 这是一个怎样的项目

- **解决什么：** 项目事实散落在聊天、各工具和口头交接里，换人或上 Agent 就要重新问一遍。
- **做成什么样：** 一个可预览、可按角色改文档、可写回仓库的知识工作空间，而不是又一个 CMS。
- **给谁用：** 研发设计、前端、产品、测试、运维、体验设计、项目与交付。
- **当前阶段：** 模版可用 / 立项 / 设计 / 研发 / 测试 / 上线 / 维护（换成当前阶段）

## 现在有什么、没有什么

**有：**

- 七个角色的分类文档（项目、产品、设计、研发、质量、交付、记录）
- 浏览器里阅读、编辑、新建 / 删除 Markdown，粘贴图片写回本地
- 授权本机目录后与 `src/content/` 同步；绑定代码空间后可提交推送

**没有（非目标）：**

- 账号体系、云端多人实时编辑
- 为每一篇文档单独做一个 Vue 页面
- 应用内 git pull / 冲突合并（现阶段只提交推送）
