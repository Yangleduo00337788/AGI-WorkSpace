把占位换成**当前项目**。这篇只回答「这是一个怎么样的项目」。工作空间怎么用见 [WorkSpace 指南](/start/guide)；为什么用这套模版见 [AGI-WorkSpace 新范式](/start/paradigm)。范围与非目标的细表见 [项目概述](/project/overview)。

任意已勾选角色都可以改本页。换项目时 PM 应牵头填完「一句话 / 用户 / 阶段」。

## 一句话

**AGI-WorkSpace**（换成当前项目名称）：按七个角色组织的项目知识工作空间。人、Agent、Git 仓库读同一份 Markdown，Vue 只做壳。

## 这是一个怎样的项目

| 问题 | 当前答案（换项目时改） |
| --- | --- |
| 解决什么 | 项目事实散落在聊天、各工具和口头交接里，换人或上 Agent 就要重新问一遍 |
| 做成什么样 | 可预览、可按角色改文档、可写回仓库的知识工作空间，不是又一个 CMS |
| 给谁用 | RD / FE / PM / QA / OP / UIUE / POM，以及协助他们的 AI Agent |
| 当前阶段 | 模版可用 / 立项 / 设计 / 研发 / 测试 / 上线 / 维护 |
| 成功长什么样 | 新成员打开工作空间，能在一次阅读内找到范围、角色、接口和发布方式 |

## 典型场景

1. **新成员第一天：** 读本页和 [项目角色](/project/roles)，勾选自己的角色，到对应目录补对接人。
2. **改需求：** PM 先改 [用户与需求](/product/users) 和 [产品需求](/product/prd)，再通知研发，而不是只在群里说一句。
3. **改写回或推送：** RD 先改 [接口契约](/engineering/contracts)，当天记入 [项目决策](/records/decisions)（若有取舍）。
4. **上 Agent：** Agent 先读 [AGENT.md](/space/harness/AGENT)，再按目录改文档或代码，不另起一套上下文。

## 现在有什么、没有什么

**有：**

- 七个角色的分类文档（项目、产品、设计、研发、质量、交付、记录）
- 浏览器里阅读、搜索、预览编辑、按角色新建 / 删除 Markdown
- 粘贴图片写到该文档 `assets/`
- 授权本机目录后与 `src/content/` 同步；绑定代码空间后可提交推送
- 开始阅读入口：首页、本页、新范式、指南

**没有（非目标）：**

- 账号体系、云端多人实时编辑、评论流、自建后端
- 为每一篇文档单独做一个 Vue 页面
- 应用内 git pull / 冲突合并（现阶段只提交推送）
- 用数据库 CMS 代替仓库里的 Markdown

## 用户与价值

| 用户 | 他们打开工作空间要完成什么 |
| --- | --- |
| 项目成员 | 找到并改完自己职责内的文档，不必问人要链接 |
| 新成员 / 接手人 | 2–10 分钟内理解范围、阶段、谁负责 |
| AI Agent | 读同一棵 `src/content/` 和 `AGENT.md`，按约束改文件 |

## 怎么维护本页

- 立项后一周内填完名称、一句话、阶段、仓库
- 阶段变化时改「当前阶段」，并同步 [项目状态](/project/status)
- 不要把接口字段、测试步骤写进本页，那些有专门文档
